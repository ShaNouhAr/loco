Fonctionnement
  1. Les postes Windows envoient leurs téléchargements à loco au lieu de Microsoft.
  2. Le premier téléchargement d'un fichier part chez Microsoft et reste en cache ; les suivants sont servis en local.
  3. Le HTTPS de ces domaines est relayé sans être déchiffré ni mis en cache : seuls les fichiers immuables sont gardés.

Deux façons d'envoyer les téléchargements Windows Update des postes vers loco :

Par DNS

Le DNS du réseau répond {{ host }} pour les domaines redirigés : couvre tout le réseau, mais demande d'éditer le DNS.

Script DNS Active Directory

Par proxy, sans DNS via l'agent activé par défaut

L'agent loco règle le proxy WinHTTP des postes Windows gérés vers {{ proxy_host }}:{{ proxy_port }} : par poste, réversible, sans toucher au DNS. Le proxy met en cache les mêmes fichiers (HTTP immuable) et relaie le HTTPS.
